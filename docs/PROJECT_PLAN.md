# 한강버스 여행 코스 프로젝트 기획서

이 문서는 네 명이 4~5일 동안 같은 목표로 움직이도록 제품 흐름과 역할 및 일정을 정리합니다  
괄호 안은 아직 팀이 확인해야 하는 제안입니다

## 1  프로젝트 목표

사용자가 한강버스 배편을 고르고 도착 예정 시각과 요금을 확인한 다음 도착지에 맞는 데이트 코스 또는 전통시장 먹거리 코스 중 하나를 선택해 계획할 수 있게 합니다

첫 버전은 실제로 자료를 확인할 수 있는 노선과 도착지만 다룹니다  
정확한 운항 정보와 장소 정보를 확보할 수 없으면 없는 정보를 만들어 시연하지 않고 이유를 표시합니다

## 2  사용자 흐름

| 순서 | 사용자 행동 | 화면이 보여줄 정보 |
|---|---|---|
| 1 | 날짜와 출발 및 도착 선착장을 선택 | 선택 가능한 조건과 검색 버튼 |
| 2 | 배편을 비교 | 출발 시각과 도착 예정 시각 및 기준 요금과 자료 확인 시각 |
| 3 | 배편을 선택 | 선택한 경로와 요금 계산 기준 |
| 4 | 데이트 코스 또는 먹거리 코스 중 하나 선택 | 두 코스의 차이와 코스 설명 |
| 5 | 추천 결과 확인 | 방문 순서와 이동 예상 시간 및 확인된 가격과 출처 |
| 6 | 자료가 부족한 경우 | 어떤 정보가 빠졌는지와 공식 안내 확인 방법 |

먹거리 코스는 도착 선착장 주변 전통시장과 실제로 확인된 먹거리 정보를 연결  
데이트 코스는 같은 도착지를 중심으로 산책이나 구경 장소를 연결  
코스는 두 가지 중 한 번에 하나만 선택

## 3  화면과 서버의 역할

| 구성 | 맡는 일 |
|---|---|
| 화면 | 출발 조건과 배편 및 코스 선택과 결과 표시 |
| 서버 | 공식 자료 조회와 저장 자료 정리 및 시간과 요금 계산 |
| 추천 기능 | 서버가 확인한 장소만 사용해 순서와 추천 이유 구성 |
| 데이터 저장소 | 배편과 선착장 및 요금과 장소 정보와 출처 및 적용 날짜 보관 |

AI가 배 시간이나 가격을 임의로 만들지 않도록 시간과 가격 계산은 서버가 담당  
추천 결과에는 사용한 장소의 자료와 확인 시각을 함께 표시

## 4  네 명 역할 제안

실명과 세부 담당은 팀원 경험에 맞춰 정합니다

| 담당 | 주 업무 | 다른 담당과 맞출 내용 |
|---|---|---|
| 1  데이터와 기획 | 시간표와 요금 및 시장 자료 확인과 사용 가능 범위 정리 | 자료 이름과 출처 및 적용 날짜를 서버 담당에게 전달 |
| 2  서버와 데이터 저장 | 자료를 저장하고 배편 검색 및 도착 시간과 요금 계산 | 화면 담당과 요청 및 응답 항목을 합의 |
| 3  화면과 사용 흐름 | 선착장과 배편 및 두 코스 선택과 결과 화면 구현 | 서버 담당과 화면에서 필요한 자료를 합의 |
| 4  기능 개발과 배포 | 기능 하나를 주 담당으로 구현하고 Docker와 EC2 배포 및 통합 | 첫날 간단한 실행을 확인하고 개발 중간마다 팀 결과를 합침 |

배포 담당도 기능 하나의 개발 책임을 함께 맡음  
배포 확인은 마지막 날에 몰지 않고 첫날 간단한 화면을 띄우는 것으로 시작

## 5  4~5일 진행 제안

| 일정 | 팀이 함께 끝낼 일 |
|---|---|
| 1일 차 | 핵심 사용자 흐름 확정  자료 사용 권한과 제공 방식을 조사  한 노선 및 도착지 후보 선택  화면과 서버 실행 확인  첫 배포 경로 확인 |
| 2일 차 | 운항과 요금 자료를 저장하고 배편 검색 구현  화면의 선택 흐름 구현  날짜와 요금 계산 기준 연결 |
| 3일 차 | 두 종류의 코스 자료를 연결  추천 결과와 출처 표시  화면과 서버를 함께 통합 |
| 4일 차 | 출발과 도착 시간 및 가격과 코스 순서를 실제 자료로 확인  자료 누락과 서비스 장애 안내  배포 환경에서 전체 흐름 점검 |
| 5일 차가 있으면 | 사용자 관점에서 시연 연습  발견된 문제 수정  발표 내용과 최종 배포 확인 |

4일 일정이면 5일 차 검토와 발표 준비를 4일 차에 포함  
매일 작업이 끝나기 전에 각자 기능을 공유 가능한 상태로 합침

## 6  첫 버전 완료 조건

- 사용자가 날짜와 선착장을 골라 배편을 찾을 수 있음
- 배편 출발과 도착 예정 시각 및 요금이 근거 자료와 일치
- 사용자가 데이트 코스 또는 먹거리 코스 하나를 선택할 수 있음
- 먹거리 코스에 도착지 주변 전통시장 정보가 포함
- 추천 장소와 확인된 이동 시간 및 가격에 출처가 연결
- 확인할 수 없는 정보는 확인 필요로 표시
- 팀원 각자가 같은 안내에 따라 실행할 수 있고 통합 배포에서 주요 흐름이 열림

## 7  먼저 확인할 위험

### 운항 정보의 자동 수집과 저장

서울시 공지에서 한강버스 운항 정보와 시간표를 확인할 수 있으나 공개 개발자 API와 자동 수집 및 재사용 허용 여부는 별도 확인이 필요  
허용된 API가 없으면 공식 자료를 사용할 수 있는 범위와 갱신 방식을 확인한 뒤 수동 반영이나 다른 허용 자료를 검토

### 도착지 주변 자료의 정확성

전통시장 이름만으로 시장 안의 개별 먹거리와 가격 및 영업시간을 알 수 있다고 가정하지 않음  
장소와 메뉴 및 운영 정보를 확인할 수 있는 자료를 확보한 범위에서 추천

### 일정 계산의 신뢰도

도착 예정 시각은 운항표 기준과 실제 운항 정보를 구분  
도보나 장소 간 이동 예상 시간에 근거가 없으면 정확한 도착을 보장하지 않음

## 8  첫날에 팀이 결정할 일

- 실제로 다룰 출발지와 도착지 한 구간
- 시간표를 받을 수 있는 공식 자료와 저장 및 표시 허용 범위
- 요금 계산에 필요한 인원과 연령 기준
- 시장 주변에서 확인할 먹거리 장소와 가격 자료
- 코스에 넣을 장소 수와 한 코스의 예상 길이
- 데이터베이스와 배포 환경
- 4명 역할 배정과 매일 통합 시각

기술 세부와 조사 결과는 [데이터 조사 문서](API_EVIDENCE.md)와 [구현 참고 문서](IMPLEMENTATION_SPEC.md)에서 확인
