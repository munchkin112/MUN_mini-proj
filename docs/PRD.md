# 한강로컬패스 PRD

## 고객 문제와 핵심 가치

고객  한강버스 이용 서울 시민과 관광객  전통시장 및 로컬 상권 방문 희망자  
사실  공식 운항과 장소 및 메뉴 정보 출처 분리  [조사 근거](API_EVIDENCE.md)  
가설  제한된 시간 내 이동과 식비 충족 판단 부담  사용자 검증 전  
가치  운항편과 방문지의 시간 및 식비 조건을 결합한 일정과 불가 사유 제공  
지도와 중복하는 장소 검색 및 길찾기는 지원 수단  통합 조건 검증의 효용은 검증 필요  

## 대표 흐름과 P0 범위

확정  한강버스 필수  4인 3일  PC 웹  가짜 서비스 데이터 금지  
설계 제안  여의도 선착장 입구 출발  1인 편도 배편 1회  시장과 식사  귀가 제외  
입력  출발일과 시각  총 180분  식비 30000원  선호와 준비 및 체류시간  
흐름  조건 입력 → 실제 도구 조회 → 후보 생성 → Python 검증 → 일정과 근거 표시  
P0  F01 조건 입력  F02 유효 배편  F03 장소 탐색  F04 일정 생성  
P0  F05 시간과 식비 검증  F06 결과와 지도 및 타임라인  F07 장애와 누락 대응  
결과  예정 기준 통과  확인 필요  조건 불충족  필수 조회 불가 구분  
식비와 운영시간 미확인은 통과 금지  확인 가능한 배편과 장소는 제한 제공  
P1  문화행사와 문화시설 확장  지정 장소 혼잡  왕복과 다인 여행  
실시간 운항과 좌석 및 대기인원은 공개 API 미확인으로 P0 구현 불가  

## 데이터와 AI 역할

현재  공식 시간표 열람 근거 확보  가공과 저장 권리 및 최신 배편 전수 대조 미완료  
현재  시장과 메뉴 및 도보 API 실제 인증 호출 미검증  현장 영업과 가격 보장 불가  
설계 제안  Planner와 Executor를 실제 Tool Calling 에이전트로 분리  
Planner  선호 해석과 후보 구성  Executor  허용 도구 선택과 근거 수집  
Python 서비스  정규화  Validator 시간과 예산 판정  Recovery 제한 재시도  
공유 상태와 호출 한도 및 스키마는 [상세 명세](IMPLEMENTATION_SPEC.md) 정의  

## 실행 계획과 완료 기준

기술  FastAPI  React Vite  PostgreSQL  Docker Compose  GitHub  LangGraph는 제안  
Day 1  A 데이터와 이용권  B 계약과 DB  C 입력 화면  D Tool 계약  종료 전 착수 판정  
Day 2  A 실제 조회  B 계산 검증  C 결과와 지도  D 에이전트 연결  핵심 경로 통합  
Day 3  실패 주입과 pytest  Docker 배포  실제 데이터 시나리오 및 지표 기록  
완료  여의도 180분과 식비 30000원 조건의 근거 있는 일정 1건  장애 안내 별도 검증  
KPI  조회 성공률  유효 일정률  검증 통과율  복구율  평균 응답시간  실측 없음  

## 위험과 최종 결정

시간표 권리와 개정 누락 → 사용범위 및 적용기간 확인 전 일정 서비스 착수 보류  
경로와 가격 및 영업정보 부족 → UNKNOWN 분리  확인 필요 안내  식비 통과 금지  
연동과 AI 작업량 초과 → 한 구간 우선  P1 제외  호출 상한  
현재 No-Go  합법적 시간표와 배편 및 최소 방문지와 경로 확보 후 재판단  
Conditional Go  예정 운항으로 제한 제공  지연과 결항 및 좌석 미확인 표시  
Go  합의한 P0 데이터와 실제 시나리오 검증 완료  예정 정보만 확보 시 Conditional Go 유지
