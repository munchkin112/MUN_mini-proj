# 한강로컬패스 PRD

서비스  한강버스와 서울 로컬 상권을 잇는 여행 일정 생성 서비스  
고객  여의도 출발 3시간 관광객  
한 문장 설명  배편과 도보 및 시장 식사를 검증해 시간과 예산 안의 일정 제공  

## 1. 고객 문제와 정상 흐름

사실  운항 일정과 시장 정보가 별도 출처에 분산  
가설  이용자가 직접 이동시간과 예산을 대조  사용자 검증 전  
가치  관광지 나열 대신 이동 가능 여부와 근거 제공  
입력  출발일과 시각 3시간  식비 3만원  혼잡 회피  
Planner  조건 구조화와 후보 작성 → Executor  운항 및 장소와 도보 조회  
→ Validator  Python 시간과 예산 판정 → 일정과 근거 또는 불가 사유  

## 2. 핵심 범위

P0 운항 조회  날짜와 선착장 → 적용 시간표  도착 전 도보시간 검증  출처와 확인시각  
P0 장소 탐색  하선 선착장 → 시장과 가격 및 영업시간 확인 식당  주소와 근거  
P0 일정 생성  입력 조건과 도구 결과 → 배편 1회와 시장 식사 후보  
P0 일정 검증  후보와 경로 → 운항 및 시간과 식비 판정  전부 통과 시 실행 가능  
P0 장애 복구  조회 오류 → 제한 재시도와 유효 캐시  없으면 사유와 함께 중단  
P1 문화행사와 지정 장소 혼잡도  실시간 운항 자동 반영 제외  

## 3. 에이전트와 데이터

Planner  입력 조건과 조회 결과 → 순서 및 체류시간 후보  선호 해석에 LLM 사용  
Executor  날짜와 좌표 → 시간표 및 장소와 가격 및 경로 조회 결과  출처  시각  
Validator  후보와 원자료 → Python으로 시간과 예산 및 누락 판정  
Recovery  오류와 캐시 상태 → 제한 재시도와 폴백 또는 중단  
전달  조건 JSON → 도구 결과 JSON → 후보 JSON → 검증 결과 JSON  
출처별 공개와 인증 및 갱신과 미검증 API는 [API 근거](API_EVIDENCE.md) 참조  
실시간 운항 API 공개 여부와 시간표 가공 권리 미확인  

## 4. 3일 실행

기술  FastAPI  React Vite  PostgreSQL  Docker  GitHub  
Day 1  A 데이터 권리와 호출  B DB와 API  C 입력 화면  D Tool 계약과 LLM 계정  
Day 2  A 데이터 연결  B 일정 검증  C 결과 화면  D Planner 연결  
Day 3  A 장애 복구  B pytest와 통합  C Docker 배포  D 실사용 시나리오  
선행조건  Day 1 내 시간표 사용권과 실제 운항 및 도보 API와 가격 확보  
완료  여의도 3시간 3만원 조건의 검증 통과 일정 1건  

## 5. 위험과 최종 판단

위험  시간표 권리와 변경 → 사용권 및 확인시각 필수  미확보 시 중단  
위험  가격과 영업정보 부족 → 검증 근거 없는 식당 제외  
위험  API 장애와 환각 → Python 재검증  실패 결과 폐기  
KPI  조회 성공률  유효 일정률  검증 통과율  복구율  평균 응답시간  실측 전 목표 미정  
범위 결정  한강버스 필수 유지  시간표 권리 또는 데이터 미확보 시 착수 보류  
최종 판단  No-Go  선행조건 충족 후 제한 구간 MVP 착수  혼잡 회피 미지원
